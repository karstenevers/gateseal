# Prepare gateseal tools before commits

Accepted on 2026-10-21 and implemented. [Design record 0010](0010-share-one-sealed-interpreter-store-across-repositories.md) narrows its prepared interpreter: commits still start the exact, verified interpreter, but from one machine-wide interpreter store instead of a copy in each attempt. The implementation is also stricter on mise than the third paragraph: a commit never starts mise, so it has no on-demand installation to disable. Each hook runs only the binaries that activation installed into the attempt, and fails closed without them.

Activation prepares the exact compiler, tools and pre-commit environments in a new attempt directory, records the prepared lock fingerprint and executables in that attempt, and publishes it through one relative link that the hook follows. Each commit pins the attempt it resolved and runs every stage from it, and activation deletes no attempt while a commit holds it. Commit hooks compare the staged lock with the pinned attempt locally before execution; missing or stale preparation requires explicit activation, while disposable CI jobs prepare deliberately before running their gate.

uv prepares environments only during activation. Commit-time compiler execution starts the exact prepared interpreter directly, so it never resolves, downloads or falls back to another interpreter, and a later uv upgrade or removal does not affect commits. Commit-time execution also disables mise's on-demand installation. Disabling installation alone is insufficient: execution must select the verified prepared binaries and fail closed rather than falling back to same-named host tools. The managed mise configuration stays separate from project configuration and must be selected without absorbing unrelated tasks, environment scripts or overrides; no shell activation or global tool changes are required.

pre-commit has no general offline execution guarantee and may rebuild missing hook environments. Activation eagerly prepares them, and local readiness checks detect missing or unhealthy preparation where possible, but a lock fingerprint is not proof that caches still exist or a network sandbox. Documentation and tests must state this limitation instead of promising that arbitrary hook code cannot reach the network.
