# Generate policy lock data and ship the runtime with the compiler

Accepted on 2026-10-27 and implemented. This supersedes the parts of [design record 0005](0005-version-policy-components-as-reviewed-catalogs.md) that make pre-commit a policy component and keep each reviewed version's artifact data in files the policy's authors write; the rest of that decision stands.

A policy author decides which versions to review and never types a URL, a commit or a SHA-256. So a policy has files people edit, `policy.toml` and the tool configuration under `rules/`, and one generated `policy.lock` that holds every derived fact: each reviewed version's revision, or each platform's archive URL, digest and executable. `gateseal policy lock` and `gateseal policy add` resolve each reviewed version from upstream, reading the commit that a release tag names and the digests in the release's checksum file, and download and check each archive before they write. `gateseal policy check` runs offline and refuses a lock that disagrees with `policy.toml`, and so do configure, activation and adoption. `policy.lock` is part of the release's content digest, as the artifact files it replaces are, so the digest that a repository's Lock records still covers every fact that decides what runs. `gateseal policy init` starts a team policy from the bundled one.

The Python and pre-commit that run gateseal leave the policy. Each compiler release carries exactly one of each as generated package data, because the compiler already fixes them in practice: it accepts one Python minor release, pre-commit's wheel closure is built for that release, and the compiler decides which pre-commit its hooks need. A pre-commit upgrade is therefore a compiler upgrade, and a pre-commit Version Exception no longer exists.

Two alternatives were rejected. One is an agent or prompt that fills in hashes, because a mistyped digest is a supply-chain failure that review rarely catches. The other lets each policy choose the runtime Python, which multiplies the interpreters and wheel sets every compiler release must test without changing what any check reports.
